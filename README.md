# vk-claude-code-bot

Бот VK для удалённого управления Claude Code. На случай, когда заказ нужно было сдать вчера, а ты в поезде.

Почему VK, а не Telegram. В поезде интернет хреновый, а иногда ещё и белые списки. Telegram в такие моменты не работает, VK работает.

Пишешь боту в личку обычным текстом — он запускает Claude Code в выбранной папке и шлёт каждое событие (текст ИИ, вызов инструмента) отдельным сообщением в чат.

Доступ только для одного человека. Бот реагирует только на твой VK user id, остальных молча игнорирует. `from_id` в Long Poll проставляет VK, подделать его нельзя.

## Команды

- `/start` — новая сессия. Показывает папки в `/home/user` и ждёт название рабочей папки.
- `/skills` — список доступных скиллов: глобальные и из текущей папки проекта.
- `/stop` — оборвать текущий ответ ИИ. Сессия сохраняется, продолжить можно следующим сообщением.
- любой текст — уходит в Claude Code.

Рабочую папку можно указать одним словом (`meet` — относительно `/home/user`) или полным путём, начинающимся с `/home`. Если папки нет — бот предложит её создать.

Сообщение во время работы ИИ прерывает текущий ответ и сразу уходит как новое. Сессия та же.

## Настройка

1. Создай сообщество VK и сделай его закрытым.
2. Включи сообщения сообщества: Управление -> Сообщения.
3. Включи Long Poll API и событие `message_new`: Управление -> Работа с API -> Long Poll API.
4. Создай ключ доступа с правами `messages` и `manage`: Управление -> Работа с API -> Ключи доступа.
5. Скопируй `.env.example` в `.env` и заполни.

```
cp .env.example .env
chmod 600 .env
```

Свой `VK_GROUP_ID` и `ALLOWED_USER_ID` можно узнать, написав боту любое сообщение — он залогирует `from_id`.

## Запуск

```
pip install -r requirements.txt
python3 bot.py
```

## Запуск как сервис

В репозитории есть `vk-claude-bot.service` — systemd user-юнит. Работает без sudo, переживает разлогин (нужен linger), сам перезапускается при падении.

```
cp vk-claude-bot.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now vk-claude-bot
loginctl enable-linger $USER
```

Управление:

```
systemctl --user restart vk-claude-bot     # после правок bot.py
systemctl --user status vk-claude-bot
journalctl --user -u vk-claude-bot -f       # логи
```

## Как это работает

Каждое сообщение запускает `claude -p` с `--output-format stream-json`. Из первого ответа берётся `session_id`, все следующие сообщения идут с `--resume <session_id>` — так держится одна сессия. `/stop` и новое сообщение во время работы просто убивают процесс, история остаётся на диске у Claude Code.

Запуск из-под бота добавляет в системный промпт запрет на `AskUserQuestion` — интерактивные диалоги бот в чате нарисовать не может, поэтому ИИ переспрашивает обычным текстом.

**Важно:**

1. Бот запускает Claude Code с `--dangerously-skip-permissions`. Это полный доступ к машине без подтверждений. Единственная защита — allowlist по `from_id`. Главный риск — угон твоего VK-аккаунта.
2. `.env` с токеном в репозиторий не коммитится. Если токен утёк — сразу отзови ключ в настройках сообщества.
3. Только текст. Картинки и вложения не обрабатываются.
